# 验收分层

## 本地开发层

用模拟进程验证配置错误、真实退出码、超时、独立日志、并发任务目录、EDA 环境隔离和 LVS 结果语义。测试不调用 Cadence，不需要 PDK，不代表版图功能验收。

Python 3.6 兼容性需要目标解释器运行测试；在更新 Python 上做语法/API 检查只是辅助。

## 目标 CentOS 7 层（全部待验）

- 新入口启动，旧 `opencode-centos7` 仍可使用，`-c` 能恢复对话。
- 实际内核版本与锁定版本一致，模型和压缩使用预期配置。
- 中文输入、Ctrl+Shift+V 粘贴、复制回复和文件导出逐项成功。
- OSC52 补丁编译后的二进制在旧终端中不再产生协议乱码。
- 注册的任务不依赖外部终端人工代跑；长任务中断对话后可查询。
- 真实 Cadence 子进程加载正确环境；错误环境明确失败。
- bridge 连到预期 GUI PID；错误 PID/PDK 时阻止设计写入。
- 源原理图与目标工作副本身份、路径和未保存状态读回正确。
- 新 CDL/GDS 的顶层、模型、端口及文本映射有实际证据。
- Calibre 完整结束，有独立报告；用真实不一致案例验证不会将 exit=0 报为通过。
- 修改前后记录和验证输入版本关联，能够打开正确工作副本并回退。

## 内部试用层（待验）

由两名工程师在各自环境完成同一测试任务。记录人工接管次数和失败情况，确认说明无需开发者口头补充即可执行，再发内部试用包。

归档测试环境、版本、输入指纹、实际报告及验收人。公司设计和 PDK 留在内部；示例/单元测试使用合成数据。
