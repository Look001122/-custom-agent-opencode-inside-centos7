# 模型连接管理

版本：0.2.0-connections.1。日期：2026-10-19。

这是可选连接管理开发分支，不是 0.1.1 品牌升级的必选配置。本轮保留现有连接方式；只有已经使用该管理器的安装才继续复用它。这里公开源码及历史验证材料，未在 GitHub 发布该内部二进制。

## 使用

运行 `xunchi-agent-centos7` 直接进入 TUI，不再在 shell 中要求 Bailian API Key。没有可用连接时显示中文“模型连接”菜单，可以按 Esc 先浏览首页。

通过 `/connections` 或 `/connect` 打开菜单。支持添加、编辑、删除多套连接，选择本次使用的连接或设为以后启动的默认连接。原生 `/models` 仍可在已配置的模型中选择；首页显示实际使用的连接名和模型。改变连接设置会重新加载服务配置；有 agent 任务运行时拒绝保存/切换，等待任务结束再进行。

每条连接包含名称、接口类型、完整 Base URL、密钥保存方式和默认模型 ID。三种接口分别为 OpenAI 兼容 Chat Completions、OpenAI Responses、Anthropic Messages。常见中转和本机兼容服务使用第一种。不是所有中转站都实现相同协议，不根据服务商名称自动猜测。

模型 ID 可以手工填写。保存后可发送一次 GET `/models` 获取列表并选择默认模型；不支持列表的服务继续手动填写。地址不自动追加 `/v1`，按服务商提供的 Base URL 填写。远程连接要求 HTTPS；HTTP 仅允许 localhost/127.0.0.1/::1 上的本机服务。

## 密钥

- 在本机记住：保存在当前用户私有目录的 `credentials.json`，目录 0700、文件 0600。本地明文保存，不等同于加密。
- 仅本次运行：保存在本次私有临时目录，正常退出后删除；连接名称和地址仍可保留，下次需要重新输入密钥。
- 无需密钥：供本机无鉴权模型等使用。
- 编辑已有且凭据可用的连接时，可以保留现有密钥，不重新显示密钥内容。

配置默认位于 `${XDG_CONFIG_HOME:-~/.config}/xunchi-agent-centos7/`。当前运行的配置与密钥临时文件位于用户缓存目录下的私有 session 子目录，正常退出时清理。SIGKILL/掉电无法保证执行清理，残留目录仍受用户权限保护。

界面只渲染星号，不将实际密钥加入命令行参数、对话、探测错误或安装包。测试中使用明显的虚假密钥，并检查原始终端输出不含密钥字节。不要把私有目录提交到 Git。

不同员工应使用各自的 Linux 用户或各自虚拟机；多人共用同一个操作系统账号不构成凭据隔离。公司统一网关、系统密钥环、OAuth 登录及组织账号管理不在此版中实现。

## 旧配置导入

优先从已有 `OPENCODE_CONFIG` 指向的 JSON 读取；否则从 `~/opencode-bailian-v1.json` 尝试导入。原文件只读，不覆盖、不删除。首次导入已有 Base URL 和模型的受支持接口，保留旧模型参数及 MCP 等其他配置；未知接口不会被猜测为兼容接口。

旧密钥若为 `{env:DASHSCOPE_API_KEY}`，保留环境变量引用，未设置变量时在 TUI 标记“需要配置密钥”，不在 shell 询问。选择编辑该连接，保存密钥后即可正常记住。已有 JSON 中直接填写的 Key 导入私有凭据文件。

管理器已经建立自己的连接列表后，不反复覆盖用户选择。原生 JSONC 和通过 `OPENCODE_CONFIG_CONTENT` 提供的高级配置尚未纳入自动导入流程；本版导入源需要标准 JSON。复杂配置应先保留原版入口核对，不能称为任意 OpenCode 配置的无损迁移。

## 显式测试

测试按钮会向所选服务发送小型请求，可能计入服务商用量；只有用户选择后才发送。普通启动、保存和切换不自动发送模型对话。

- 普通对话测试：确认接口能返回文本。
- 工具调用格式测试：请求一个无副作用的 `xunchi_probe` 调用，校验名称和 JSON 参数；不会执行该工具或任何 shell 命令。
- 工具格式通过不代表 Virtuoso 操作或实际电路验证已经通过。图像输入、复杂工具链、长上下文等仍需分别测试。

鉴权失败、额度/限流、接口缺失、DNS、TLS、超时和不符合要求的响应有中文结果页。错误不显示远端响应正文，地址跳转不会携带凭据自动跟随。失败不自动切换到其他服务商。

本轮开发验证使用本机模拟服务，未使用或请求员工的真实密钥/模型账户。目标 CentOS 7、新服务商的真实对话和工具能力待用户更新后验收。
