# 2026-10-19：XunChi Agent 品牌与身份统一

今天把公司定制从启动页扩展到完整的产品身份：界面和模型能分别说明“这是哪个产品”和“当前调用哪个模型”，同时保留工程师已经配置好的连接方式，减少升级时重新配置环境的工作。

## 交付内容

- **XunChi Agent 0.1.1**：统一首页、窗口、侧栏默认实现与内置插件、帮助、命令行标识、退出摘要及恢复命令。增加 `/about` 展示公司、独立产品版本、OpenCode 上游来源和当前模型。
- **助手身份**：请求系统提示增加统一身份；十份模型默认提示词开头同步修改，保留任务执行、规划、工具使用和权限规则。恢复会话不改写历史消息，产品名称与真实模型名称分开。
- **保留连接方式的升级器**：识别现有启动入口，复制已有运行库和启动脚本，选择 legacy 或 managed 对应引擎。升级前后按字节核对启动文件，保留 provider/model 配置、凭据和会话；新目录安装，支持恢复升级前入口。
- **可选连接管理源码**：保存今天已完成的中文多连接管理开发分支，支持三种 API 协议、模型选择、私有凭据、默认/本次连接区分及显式测试。品牌升级不会要求用户启用该分支。

## 验证

内部引擎在固定 OpenCode 1.19.0 提交和 Bun 1.3.14 下构建，相关核心/TUI 类型检查通过。部署代码通过 Python 3.6 语法检查。

在 WSL 隔离 HOME/tmux 中，对真实编译程序检查 CLI 帮助、首页/侧栏/窗口、关于页、中文粘贴、退出恢复以及会话恢复。本机模拟接口捕获 Build、Plan、自定义 agent 和恢复会话的系统提示；实际 read 工具成功读取测试标记且文件未变。对两种既有启动方式，从最终内部升级包完成真实安装、运行和回退，原配置未变、启动脚本字节一致。

从本次待提交目录重新运行全部 **36 项 Python 测试，全部通过**；部署脚本通过 Python 3.6 语法检查，构建和安装脚本通过 shell 语法检查。源码测试包含进程机制、终端兼容、连接管理和升级器。GitHub Actions 会对该提交继续检查，具体 CI 结果以 Actions 页面为准。

## 证据边界

本次没有请求真实员工模型账户，也没有连接或修改 Virtuoso、PDK 或设计数据。新版 CentOS 7 实机、真实 DeepSeek 回答和 Virtuoso 连接仍需验收。模拟回复不能证明真实模型一定按身份提示回答，旧版的成功反馈不能直接作为新版验收。

本次公开源码、补丁、模板、测试和不含个人配置的历史构建摘要；没有上传品牌二进制、运行库、凭据、会话、内部模型地址、PDK 或设计文件。旧 r1 Release 保留原样。构建记录中的 SHA 只标识内部产物，不表示相应二进制可以从此仓库下载。
